Benchmarks

Each benchmark runs DES on a problem with a known answer, an analytical solution, a theoretical prediction or an independent calculation, and shows how close DES comes and where the comparison stops. The inputs are in the DynEarthSol repository; each page says how to run them and what to expect.

DynEarthSol is also checked against stored results to catch unintended changes, and by functional tests that run in continuous integration; both are listed below.

Regression tests​

tests/regression/ guards against unintended changes in results. A run of a reference case is stored, and later runs are compared field by field:

cd tests/regression
make set                 # run once with the current executable and store the result
make cmp                 # rerun and compare with the stored result
make fresh-restart-cmp   # run, restart from a checkpoint and compare: restart determinism

CASE selects the input (default test-3d-equ-tiny.cfg), NDIMS the dimension and OMP the thread count. The comparison script compare.py reports the relative difference of every field and fails above 10−8 or on a non-finite value. A change to the solver that may alter results is checked by make set with the parent revision and make cmp with the change; see Testing.

Continuous integration​

Every pull request to DynEarthSol builds the code with several compilers and options (GCC 8–15, C++20 compatibility, macOS, NVHPC for OpenACC, MMG, ExodusII and GoSPL builds) and runs the functional tests:

  • a 3D elasto-visco-plastic model with remeshing and a temperature dome, and its restart determinism;
  • a 2D elastoplastic model on an irregular mesh with remeshing, and its restart determinism;
  • the plane-strain elastic update and homogeneous initial stress checks;
  • a subset of the RSF simple-shear benchmark;
  • rejection of malformed input files;
  • a 3D run in a debug build to catch memory errors.
